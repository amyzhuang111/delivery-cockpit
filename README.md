# Delivery Cockpit

A one-page delivery view for a human-data project, built as an interview project for the Strategic Projects Lead (Deeptune) role at Mercor. **Not affiliated with Mercor.**

Panels: daily rate vs deadline · acceptance rate by vendor / pod / contributor · reviewer load · **contributor ramp** (recruited → screened → trained → first accepted task → productive, drop-off per stage, time to productivity, "can we onboard N by date X") · decision log.

## Data honesty
- `public/data/illustrative-*.csv` are **ILLUSTRATIVE DATA**: synthetic, generated by `scripts/gen-illustrative.mjs` (seeded). The stage rates in them are invented for the demo.
- The optional "published anchors" forecast mode uses two cited figures: 13% passed a qualification task (26/200, Zhang et al., ACL 2023, https://aclanthology.org/2023.acl-long.835/) and 20% of tutorial completers qualified (Nangia et al., ACL 2021, https://aclanthology.org/2021.acl-long.98/). Both come from academic MTurk pipelines for hard NLP tasks, so treat them as a pessimistic anchor.
- Uploaded CSV/XLSX files are parsed in the browser. Nothing is uploaded to a server.

## How to use
1. Open the site. It loads the illustrative CSVs.
2. Set target + deadline to see the required vs actual daily rate.
3. Upload a task-review export (CSV or XLSX; every sheet is listed and you pick one, first by default) (who, outcome, plus optional team/vendor/reviewer/date). Header names are matched fuzzily.
4. Upload a contributor export (CSV or XLSX, with a sheet picker; one row per person, one date column per stage; blank = not reached). The page states whether it read dates as DD/MM or MM/DD (decided per file: a first part >12 proves DD/MM, a second part >12 proves MM/DD, otherwise US MM/DD is assumed and said so) and flags rows whose stage dates go backwards.
5. Enter N, the date and recruits/day capacity to get a yes/no verdict, the recruits/day you'd need, and the earliest feasible date.
6. Click **Run the 1,000-in-3-days check** for the demo scenario.

## Dev
Static site, no build step. `public/` is deployed as-is. Inter is self-hosted (`public/fonts`, SIL OFL).
```
npm test                       # unit tests (node:test)
E2E_URL=https://… npm run e2e  # puppeteer-core e2e against a live URL (needs Chrome)
node test/shots.mjs <url> live # 1440 + 375 screenshots into shots/
gitleaks git . && gitleaks dir . # secrets scan before every push
python3 test/fixtures/make-ramp-xlsx.py  # regenerates the XLSX fixture (openpyxl)
```
